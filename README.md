# Fighter API

REST API для каталога истребителей на Python и FastAPI. Приложение позволяет создавать записи, получать весь каталог или отдельный истребитель, обновлять его характеристики и удалять записи.

Данные хранятся в памяти процесса. При каждом запуске загружаются три начальные записи: `1` — F-16 Fighting Falcon, `2` — F-15 Eagle, `3` — F/A-18A Hornet. Изменения теряются после остановки или перезагрузки сервера, в том числе при автоматической перезагрузке с `--reload`.

## Установка и запуск

Нужны Python 3.11 или новее и `pip`. Зависимости зафиксированы в `requirements.txt`; текущее окружение проекта использует Python 3.15.

Все команды выполняйте из папки `1/fighter`, где находится `main.py`. Если окружение `venv` уже создано, шаг его создания можно пропустить. Активация окружения для приведённых команд не требуется.

### Windows (PowerShell)

Перейдите в папку проекта, затем создайте окружение и установите зависимости:

```powershell
cd "путь\к\1\fighter"
py -m venv venv
.\venv\Scripts\python.exe -m pip install -r requirements.txt
```

Запустите сервер:

```powershell
.\venv\Scripts\python.exe -m uvicorn main:app --reload
```

### Linux/macOS

```bash
cd "путь/к/1/fighter"
python3 -m venv venv
./venv/bin/python -m pip install -r requirements.txt
./venv/bin/python -m uvicorn main:app --reload
```

После запуска:

- базовый адрес API — `http://127.0.0.1:8000`;
- [Swagger UI](http://127.0.0.1:8000/docs) — интерактивная документация для выполнения запросов;
- [проверка состояния](http://127.0.0.1:8000/health) — возвращает `200 OK` и `{"status":"OK"}`.

Для остановки сервера нажмите `Ctrl+C` в его терминале.

## Свойства истребителя

Объект содержит семь свойств:

| Свойство | Тип | Описание | Ограничение |
| --- | --- | --- | --- |
| `id` | `int` | Уникальный идентификатор записи | Положительный; назначается сервером |
| `name` | `str` | Название истребителя | Непустая строка после удаления пробелов по краям |
| `engine_count` | `int` | Количество двигателей | Больше нуля |
| `mass_kg` | `float` | Масса самолёта в расчётной модели, кг | Больше нуля |
| `wingspan_m` | `float` | Размах крыла, м | Больше нуля |
| `wing_area_m2` | `float` | Площадь крыла, м² | Больше нуля |
| `mean_aerodynamic_chord_m` | `float` | Средняя аэродинамическая хорда, м | Больше нуля |

При создании и обновлении обязательны все шесть свойств, кроме `id`. Идентификатор передавать в JSON нельзя: при создании он назначается автоматически, а при обновлении берётся из адреса запроса и сохраняется. Дополнительные поля запрещены. Значения `NaN` и бесконечности не допускаются.

Пример существующего объекта с `id=1`:

```json
{
  "id": 1,
  "name": "F-16 Fighting Falcon",
  "engine_count": 1,
  "mass_kg": 9295.44,
  "wingspan_m": 9.144,
  "wing_area_m2": 27.87,
  "mean_aerodynamic_chord_m": 3.45
}
```

## Доступные действия

Все пути в таблице добавляются к базовому адресу `http://127.0.0.1:8000`. Вместо `{fighter_id}` подставляется целочисленный идентификатор записи.

| Метод | Путь | Действие | Успешный ответ |
| --- | --- | --- | --- |
| `GET` | `/api/v1/fighters/` | Получить весь каталог | `200 OK`, массив объектов; при пустом каталоге — `[]` |
| `GET` | `/api/v1/fighters/{fighter_id}` | Получить один истребитель | `200 OK`, объект истребителя |
| `POST` | `/api/v1/fighters/` | Создать запись | `201 Created`, созданный объект с назначенным `id` |
| `PUT` | `/api/v1/fighters/{fighter_id}` | Полностью обновить характеристики существующей записи | `200 OK`, обновлённый объект с прежним `id` |
| `DELETE` | `/api/v1/fighters/{fighter_id}` | Удалить запись | `200 OK`, удалённый объект |
| `GET` | `/health` | Проверить состояние приложения | `200 OK`, `{"status":"OK"}` |

`PUT` требует полный набор характеристик. Пропущенные свойства не сохраняются автоматически: запрос без любого обязательного свойства будет отклонён. Если записи с указанным идентификатором нет, `PUT` возвращает `404`, новую запись он не создаёт.

## Использование через Swagger UI

Запустите сервер и откройте [Swagger UI](http://127.0.0.1:8000/docs). Для каждого запроса раскройте нужную операцию, нажмите **Try it out**, заполните параметры и нажмите **Execute**. Ответ появится в разделе **Server response**.

### 1. Получить каталог или отдельную запись

Выполните `GET /api/v1/fighters/`. Сразу после запуска он возвращает массив из трёх начальных объектов.

Чтобы получить только F-16, выберите `GET /api/v1/fighters/{fighter_id}` и введите `1` в поле `fighter_id`. Ответ соответствует примеру объекта выше.

### 2. Создать запись

Выберите `POST /api/v1/fighters/` и вставьте в **Request body** следующий JSON. Это учебная запись для проверки операций:

```json
{
  "name": "F-16 Fighting Falcon (demo)",
  "engine_count": 1,
  "mass_kg": 9295.44,
  "wingspan_m": 9.144,
  "wing_area_m2": 27.87,
  "mean_aerodynamic_chord_m": 3.45
}
```

Ожидается `201 Created` и объект с теми же характеристиками и новым `id`. Если после запуска ещё не создавались записи, его идентификатор — `4`. Сохраните фактически полученный `id` для следующих действий. В пределах одного запуска идентификаторы назначаются последовательно и после удаления повторно не используются.

### 3. Обновить запись

Выберите `PUT /api/v1/fighters/{fighter_id}`, введите идентификатор созданной записи и передайте полный объект характеристик. Например, измените название учебной записи и её массу:

```json
{
  "name": "F-16 Fighting Falcon (updated demo)",
  "engine_count": 1,
  "mass_kg": 9400.0,
  "wingspan_m": 9.144,
  "wing_area_m2": 27.87,
  "mean_aerodynamic_chord_m": 3.45
}
```

Ожидается `200 OK` и обновлённый объект. Его `id` остаётся прежним. Повторите `GET` по этому идентификатору, чтобы увидеть сохранённые изменения.

### 4. Удалить запись

Выберите `DELETE /api/v1/fighters/{fighter_id}` и укажите идентификатор учебной записи. Ожидается `200 OK` и удалённый объект в теле ответа.

Повторный `GET` или `DELETE` по тому же идентификатору вернёт `404 Not Found`. В общем списке эта запись больше не отображается.

## Использование через Postman

Создайте запрос, укажите метод и полный адрес из таблицы, например `GET http://127.0.0.1:8000/api/v1/fighters/`, затем нажмите **Send**.

Для `POST` и `PUT` выберите **Body → raw → JSON** и вставьте соответствующий пример тела запроса из раздела о Swagger. Заголовок должен быть `Content-Type: application/json`. Для `GET` и `DELETE` тело запроса не требуется.

## Ошибки запросов

| Код | Когда возникает |
| --- | --- |
| `404 Not Found` | Запись с указанным целочисленным идентификатором отсутствует при `GET`, `PUT` или `DELETE` |
| `422 Unprocessable Entity` | Пропущено обязательное свойство, передано лишнее поле, недопустимое значение или нецелочисленный идентификатор в адресе |

Ответ для отсутствующей записи:

```json
{"detail":"Истребитель не найден"}
```

При ошибке валидации ответ содержит массив `detail` с указанием проблемных полей и причин ошибки. Например, создание записи с `mass_kg=0` или обновление только одного поля без остальных обязательных свойств вернёт `422`.
